## Frozen research question

Which remedies from the prior, fully independent mathematics/algorithm/coding study can be converted into a concrete, bounded, Rust-first code-task specification that is reproducible, source-localized, falsifiable, and eligible for a later implementation decision, without implementing a patch or claiming solver, endpoint, scientific, or production progress now?

## Frozen subquestions

1. Which prior remedies repair confirmed current false-success defects, which are only discriminators, and which remain no-go or retained blockers?
2. What exact files, symbols, call paths, data flows, state dimensions, dependency versions, and tests govern each candidate?
3. What observable acceptance signal would distinguish a real repair from common-mode parity, a static receipt, or segment-only progress?
4. Among no more than three materially different candidates, which has the best expected hard-blocker movement per line and validation wall-time?
5. What must a later implementation run prove, and what evidence is explicitly insufficient?

## Frozen hypotheses and falsifiers

- H1: Raw accepted-state admission in the dynamic collision driver is a small, source-local correctness repair that can prevent clipped observables from laundering invalid states. Falsifier: current consumers already admit the raw state before every clip-derived observable, or the proposed predicate cannot distinguish the documented counterexample.
- H2: A typed NumPy Rodas event/admission repair can remove the fabricated-terminal-event and adjacent false-success classes in one existing state machine. Falsifier: the affected solver is unreachable, or exact source inspection shows typed exhaustion, event evidence, work counters, and fail-closed consumers already exist.
- H3: A moment-constrained slow-manifold discriminator with a full-grid residual and adjoint QoI certificate is the only seeded candidate with a plausible route beyond the derivative-only D-071 no-go. Falsifier: rank grows with grid order; no usable coercivity or branch uniqueness exists; conservation, positivity, tail, or QoI bounds fail; or certificate cost erases projected gain.
- H4: Generic Jacobian, solver swaps, tolerance tuning, retry policies, and cheap-segment optimization are insufficient as first candidates. Falsifier: a current same-physics work model and reproducible full-prefix result meet both 5,500-call and 64,800-second caps with raw-state/scientific gates preserved.

## Frozen method

1. Bind the prior 34-finding adjudication and ranked seeds to exact hashes.
2. Reconstruct a current exact-head reproduction/acceptance baseline without executing endpoint or implementation work.
3. Delegate one registered context mapper to own source localization; avoid duplicate broad discovery.
4. Compare at most three bounded solution designs and write an execution plan and separated validation matrix.
5. Submit the packet to one independent adversarial design review and one final adjudication. No sibling result is visible before its registered phase permits it.
6. Do not modify production source, tests, gates, registries, or shared scientific documents.

## Frozen acceptance and stopping rules

- All three prior ranked seeds and all explicitly not-ranked remedy classes are dispositioned; none silently disappears.
- Every candidate has exact insertion points, behavior change, compatibility boundary, smallest falsification test, scientific/numerical requirements, rollback, and residual claim ceiling.
- There are at most three candidates and one selected next code task at most; a design may instead be held or rejected.
- Phase 5 and runtime/diff validations are never reported as executed.
- One independent review round and one final adjudication are the maximum.
- Stop with PROMOTE_FOR_LATER_IMPLEMENTATION, HOLD, REWORK, or REVERT_DESIGN; none of these changes current repository gates.

FROZEN: the research question, hypotheses, falsifiers, method, acceptance, and stopping rules above are immutable for this work unit.
